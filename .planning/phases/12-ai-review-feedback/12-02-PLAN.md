**File: src/app/api/feedback/employer/route.ts**

```ts
/*
 * POST /api/feedback/employer
 * Validates JWT token, creates EmployerFeedback record, marks FeedbackRequest
 * as used, and triggers Hiretivo Score recalculation.
 * No auth required — public endpoint gated by JWT token validity.
 * Rate limited: 10 req/min per IP (low volume, no auth).
 * Body: { token: string, rating: number (1-5), comment?: string }
 * Returns 200 on success, 400 on invalid/expired/used token.
 */
```

Implementation:
1. Rate limit: `createRateLimiter("feedback-submit", 10, "1 m")` at module scope
2. Zod validation: `z.object({ token: z.string().min(1), rating: z.number().int().min(1).max(5), comment: z.string().max(2000).optional() })`
3. Verify JWT: call `verifyFeedbackToken(token)` — catch `JWTExpired` → return `{ error: 'expired' }` 400; catch `JWSInvalid` → return `{ error: 'invalid_token' }` 400
4. Hash token: `const tokenHash = hashToken(token)`
5. Look up FeedbackRequest: `prisma.feedbackRequest.findUnique({ where: { tokenHash } })`
   - Not found → return `{ error: 'invalid_token' }` 400
   - `usedAt` is not null → return `{ error: 'already_used' }` 400
   - `expiresAt < new Date()` → return `{ error: 'expired' }` 400
6. Verify payload matches DB record: `payload.engineerId === record.engineerId && payload.feedbackRequestId === record.id` → 400 if mismatch (prevents token forgery)
7. Create EmployerFeedback + mark FeedbackRequest used in a transaction:
   ```ts
   await prisma.$transaction([
     prisma.employerFeedback.create({
       data: {
         engineerId: record.engineerId,
         recruiterId: record.recruiterId,
         jobId: record.jobId,
         feedbackRequestId: record.id,
         rating: parsed.data.rating,
         comment: parsed.data.comment,
       }
     }),
     prisma.feedbackRequest.update({
       where: { id: record.id },
       data: { usedAt: new Date() }
     })
   ])
   ```
8. Score recalc (LOCKED formula from CONTEXT.md):
   ```ts
   const latestReview = await prisma.verificationReview.findFirst({
     where: { userId: record.engineerId, status: 'VERIFIED' },
     orderBy: { createdAt: 'desc' }
   })
   const scoreGiven = latestReview?.scoreGiven ?? 50
   const { _avg } = await prisma.employerFeedback.aggregate({
     where: { engineerId: record.engineerId },
     _avg: { rating: true }
   })
   const avgRating = _avg.rating ?? 0
   const newScore = Math.round(scoreGiven * 0.85 + (avgRating / 5 * 100) * 0.15)
   await prisma.user.update({
     where: { id: record.engineerId },
     data: { hiretivoScore: newScore, scoreUpdatedAt: new Date() }
   })
   ```
9. Return `Response.json({ success: true })`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → /feedback/[token] | No-auth page; token is only gate |
| Public internet → /api/feedback/employer | No-auth API; JWT + DB state are only gates |
| Vercel scheduler → /api/cron/feedback-requests | Cron must only be callable by Vercel |
| feedback-token.ts → FEEDBACK_SECRET env var | Secret controls JWT signing/verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-01 | Tampering | JWT token payload (engineerId, feedbackRequestId) | mitigate | verifyFeedbackToken checks HMAC signature with FEEDBACK_SECRET; route also cross-checks payload fields against DB record (`payload.engineerId === record.engineerId`) — tampered tokens fail both checks |
| T-12-02-02 | Repudiation | Feedback submission | mitigate | FeedbackRequest.usedAt timestamp is set atomically in same transaction as EmployerFeedback create; provides non-repudiation |
| T-12-02-03 | Denial of Service | Feedback submit endpoint (public, no auth) | mitigate | Rate limit 10 req/min per IP via createRateLimiter("feedback-submit", 10, "1 m") |
| T-12-02-04 | Spoofing | /api/cron/feedback-requests called by attacker | mitigate | `Authorization: Bearer ${CRON_SECRET}` header required; missing/wrong secret → 401; cron creates FeedbackRequests so spoofing would waste compute but not expose data |
| T-12-02-05 | Elevation of Privilege | Reuse of expired/used JWT to submit multiple feedbacks | mitigate | Three-layer check: (1) jwtVerify throws JWTExpired, (2) DB expiresAt check, (3) DB usedAt not-null check; any layer blocks reuse |
| T-12-02-06 | Information Disclosure | Token leakage via logs | mitigate | Never log the raw JWT token; only log tokenHash (sha256 is one-way); email sends token in URL, not in logs |
| T-12-02-07 | Tampering | score recalc formula | accept | Formula uses only DB-persisted values (scoreGiven from admin-reviewed VerificationReview, avgRating from DB aggregate); no client input affects formula inputs directly |
| T-12-02-08 | Injection | comment field stored as text | mitigate | Stored as `@db.Text` in Prisma, parameterized query — no SQL injection; rendered in admin UI must use `textContent` not `innerHTML` (note for Plan 12-01 admin form) |
</threat_model>
