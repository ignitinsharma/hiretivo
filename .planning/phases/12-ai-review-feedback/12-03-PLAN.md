```ts
/*
 * GET /api/recruiter/pipeline
 * Returns all applications for the authenticated recruiter's jobs,
 * grouped by status into 6 columns (APPLIED/REVIEWING/INTERVIEW/OFFER/HIRED/REJECTED).
 * Name blur: if no EngineerUnlock record exists for this recruiter+engineer pair,
 * returns blurredName (first initial + last initial) instead of full name.
 * Auth: RECRUITER role required.
 * Rate limited: 30 req/min per IP.
 * Returns: { columns: Record<AppStatus, PipelineCard[]> }
 */
```

Implementation:
1. Import `dataFetchRateLimiter`, `getRateLimitIp` from `@/lib/rate-limit`; apply rate limit
2. Auth: `const session = await auth()` → 401 if no session, 403 if role !== RECRUITER
3. Query all applications for recruiter's jobs:
   ```ts
   const applications = await prisma.application.findMany({
     where: { job: { recruiterId: session.user.id } },
     include: {
       job: { select: { title: true } },
       seeker: { select: { id: true, name: true } },
     },
     orderBy: { createdAt: 'desc' },
   })
   ```
4. Batch fetch unlocks for this recruiter:
   ```ts
   const unlocks = await prisma.engineerUnlock.findMany({
     where: { recruiterId: session.user.id },
     select: { engineerId: true },
   })
   const unlockedIds = new Set(unlocks.map(u => u.engineerId))
   ```
5. Transform each application into `PipelineCard`:
   ```ts
   interface PipelineCard {
     id: string         // applicationId
     engineerId: string
     engineerName: string   // full name if unlocked, blurred if not
     isBlurred: boolean
     jobTitle: string
     matchScore: number
     appliedAt: string   // ISO date string
     status: AppStatus
   }
   ```
   Name blur logic: `if (!unlockedIds.has(app.seeker.id)) { blurName = firstInitial + '. ' + lastInitial + '.' }` — split `app.seeker.name` on space; if single word use first 2 chars + '.'
6. Group into columns:
   ```ts
   const columns: Record<string, PipelineCard[]> = {
     APPLIED: [], REVIEWING: [], INTERVIEW: [], OFFER: [], HIRED: [], REJECTED: []
   }
   for (const card of cards) columns[card.status].push(card)
   ```
7. Return `Response.json({ columns })`

```ts
/*
 * PATCH /api/recruiter/application/[id]/status
 * Moves an application to a new status column in the pipeline kanban.
 * Only the job's owning recruiter may update the status.
```

Implementation:

6. Return `Response.json({ id, status: parsed.data.status })`

Optimistic update on move:
```ts
onMutate: async ({ id, status }) => {
  await queryClient.cancelQueries({ queryKey: ['pipeline'] })
  const prev = queryClient.getQueryData(['pipeline'])
  queryClient.setQueryData(['pipeline'], (old: any) => {
    // Remove card from old column, add to new column
    const columns = { ...old.columns }
    for (const col of Object.keys(columns)) {
      columns[col] = columns[col].filter((c: PipelineCard) => c.id !== id)
    }
    const card = Object.values(old.columns).flat().find((c: any) => c.id === id)
    if (card) columns[status] = [{ ...card, status }, ...columns[status]]
    return { columns }
  })
  return { prev }
},
onError: (_err, _vars, ctx) => queryClient.setQueryData(['pipeline'], ctx?.prev),
onSettled: () => queryClient.invalidateQueries({ queryKey: ['pipeline'] }),
```

| Recruiter browser → GET /api/recruiter/pipeline | Authenticated; returns potentially blurred engineer PII |
| Recruiter browser → PATCH /api/recruiter/application/[id]/status | Authenticated write; must own the application's job |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03-01 | Elevation of Privilege | PATCH /api/recruiter/application/[id]/status — recruiter updates another recruiter's application | mitigate | Ownership check: fetch application with job.recruiterId, compare to session.user.id; return 403 if mismatch |
| T-12-03-02 | Information Disclosure | GET /api/recruiter/pipeline returns unblurred engineer names | mitigate | Blur logic: check EngineerUnlock table per engineer; only return full name if unlock record exists for this recruiter+engineer pair |
| T-12-03-03 | Spoofing | Unauthenticated access to pipeline routes | mitigate | Auth.js session check on both routes; 401 if no session; 403 if wrong role |
| T-12-03-04 | Denial of Service | Pipeline board loads all recruiter applications | mitigate | dataFetchRateLimiter (30/min); add `take: 200` cap in findMany query to prevent unbounded result sets for large recruiters |
| T-12-03-05 | Tampering | status value in PATCH body is arbitrary string | mitigate | Zod enum validation with exact AppStatus values; invalid values rejected with 400 before DB update |
</threat_model>
