## Component Interaction Map

This section specifies the interaction contracts the executor must wire. The visual components exist; these are the data-binding requirements.

### PostJobModal (Dialog)

**Trigger:** "Post New Job" button on My Jobs page → calls `openPostJobModal()` from `use-ui-store`
**Close:** Cancel button + Dialog `onOpenChange` → calls `closePostJobModal()`

**Primary focal pair:** The "Post New Job" button and the H1 "Active Jobs" form the primary focal pair on the My Jobs page. These two elements anchor the page's purpose and should remain visually dominant relative to all other controls.

| Field | Component | Wiring |
|-------|-----------|--------|
| Job Title | Input | Controlled — `react-hook-form` field `title` (required, non-empty string) |
| Category | Select | Controlled — `react-hook-form` field `category`. Options: Engineering, Design, Marketing, Data, DevOps, Product, Other |
| Job Type | Select | Controlled — `react-hook-form` field `jobType`. Maps to JobType enum: FULL_TIME, PART_TIME, CONTRACT, INTERNSHIP |
| Experience Level | Select | Controlled — `react-hook-form` field `experienceLevel`. Options: Entry, Mid-level, Senior, Lead, Executive |
| Compensation Range | Input | Controlled — `react-hook-form` field `salaryText`. Free text; parsed on submit to salaryMin/salaryMax/currency integers |
| Job Description | Textarea | Controlled — `react-hook-form` field `description`. `min-h-[120px] resize-none` preserved. No rich text — plain textarea V1. |
| Required Skills | Multi-select tag UI | Controlled — array of `{ skillId: string, name: string }`. Populated from `GET /api/skills`. Selected skills render as removable pill tags with `X` icon (`aria-label="Remove {skillName}"`). Input below allows filtering/search (client-side, no extra API call). Minimum 1 skill required — form submit blocked if empty. |
| Apply Type | (wire via hidden or extend Select) | `react-hook-form` field `applyType`: INTERNAL or EXTERNAL. If EXTERNAL, show additional Input for `externalUrl`. |
| Location | Input (add if not present) | `react-hook-form` field `location`. Free text. |

**Submit flow:**
1. `react-hook-form` validates all fields client-side
2. POST `/api/jobs` with form payload
3. On 403 (plan gate): display Sonner toast — error variant — "FREE plan allows 1 active job. Upgrade to post more."
4. On 400 (validation error from server): display Sonner toast — error variant — with server error message
5. On 201 success: close modal + invalidate React Query `['jobs']` cache

### My Jobs Page (Table + CRUD)

**Data source:** `GET /api/jobs` via `useQuery({ queryKey: ['jobs'] })`
**Loading state:** Show Skeleton rows (4 rows, matching table row height) while `isLoading`
**Empty state:** See Copywriting Contract below

| Action | Trigger | Mutation |
|--------|---------|----------|
| Toggle Active/Inactive | Dropdown → "Archive Job" | `PATCH /api/jobs/[id]` `{ status: 'PAUSED' }` (ACTIVE→PAUSED) or `{ status: 'ACTIVE' }` (PAUSED→ACTIVE). Label switches between "Archive Job" and "Reactivate Job" based on current status. |
| Edit Job | Dropdown → "Edit Job" | Opens PostJobModal pre-populated with existing job data. Submit calls `PATCH /api/jobs/[id]` with full form payload. |
| Delete Job | Dropdown → "Delete Job" | Inline confirmation (see Copywriting Contract). On confirm: `DELETE /api/jobs/[id]`. |

**On mutation success:** Invalidate `['jobs']` query. Show Sonner toast (success variant). No page reload.

### Skills Picker (inside PostJobModal)

- Fetch all skills on modal open: `GET /api/skills` → response: `{ id, name, category }[]`
- Group by category in dropdown/search results: Engineering, Design, Marketing, Data, DevOps, Product, Other
- Client-side filter: debounce 200ms on Input `onChange`
- Selected skills rendered as pill tags (existing `bg-primary/10` pill style)
- `X` on tag removes skill from selection array; each `X` button must carry `aria-label="Remove {skillName}"` (e.g. `aria-label="Remove React"`)
- Minimum 1 skill enforced — submit button disabled + inline error shown if 0 skills

## State Inventory

States the executor must handle for each surface:

### My Jobs Page

| State | Trigger | UI Behavior |
|-------|---------|-------------|
| Loading | `isLoading` from useQuery | Replace table body with 4 skeleton rows |
| Empty | `data.length === 0` | Replace table body with centered empty state (heading + body + CTA) |
| Populated | `data.length > 0` | Render job rows with live data |
| Error | `isError` from useQuery | Sonner toast "Something went wrong. Please try again." + show empty state |

### PostJobModal

| State | Trigger | UI Behavior |
|-------|---------|-------------|
| Closed | `isPostJobModalOpen === false` | Dialog not mounted |
| Open (create) | `isPostJobModalOpen === true`, no `editJobId` | Form blank, CTA = "Publish Job Post" |
| Open (edit) | `isPostJobModalOpen === true`, `editJobId` set | Form pre-populated with job data; CTA = "Update Job Post" |
| Submitting | Form submit in-flight | Submit button disabled + shows loading spinner; Cancel button enabled |
| Skills loading | `GET /api/skills` in-flight on modal open | Input shows placeholder "Loading skills..." |
| Plan gate error | 403 response | Toast error; modal stays open |
