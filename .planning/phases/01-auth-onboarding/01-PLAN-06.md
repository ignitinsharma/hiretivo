    Edit `src/auth.ts` to add a `signIn` callback in the `callbacks` object. This callback intercepts Google OAuth logins and redirects new Google users to the role-selection page.

    **Strategy:** Mark the JWT token with `needsRoleSelection: true` when a Google user logs in and their role is still the default SEEKER (which means they haven't explicitly chosen). The `signIn` callback can redirect the user.

    In Auth.js v5, the `signIn` callback receives `{ user, account, profile }`. When `account?.provider === "google"`, we check if this is effectively a "new" session. The cleanest approach: use the `redirectTo` mechanism.

    Add the `signIn` callback INSIDE the existing `callbacks` object (alongside `jwt` and `session`):

    ```typescript
    async signIn({ user, account }) {
      // Only intercept Google OAuth — Credentials provider handles role via register
      if (account?.provider !== "google") return true;

      // Check if the user has explicitly set their role
      // Since role defaults to SEEKER, we check if they have a SeekerProfile or RecruiterProfile
      // to determine if they've been through onboarding. For brand-new Google users, neither exists.
      if (!user.id) return true;

      const dbUser = await prisma.user.findUnique({
        where: { id: user.id },
        select: {
          seekerProfile: { select: { id: true } },
          recruiterProfile: { select: { id: true } },
        },
      });

      const hasProfile = dbUser?.seekerProfile || dbUser?.recruiterProfile;

      if (!hasProfile) {
        // New Google user — redirect to role selection page
        // Return URL string redirects the user in Auth.js v5
        return `/auth/select-role?userId=${user.id}`;
      }

      return true;
    },
    ```

    CRITICAL: Add this callback INSIDE the existing `callbacks: { ... }` object block, after the `session` callback. Do not create a second `callbacks` key. Do not alter the `jwt` or `session` callbacks in any way.

    **Part A: Create server action src/app/actions/auth/set-role.ts**

    ```typescript
    "use server";

    import { auth, signIn } from "@/auth";
    import { prisma } from "@/lib/prisma";
    import { Role } from "@prisma/client";

    type RoleResult = { success: true; redirectTo: string } | { success: false; error: string };

    export async function setUserRole(role: "SEEKER" | "RECRUITER"): Promise<RoleResult> {
      const session = await auth();
      if (!session?.user?.id) {
        return { success: false, error: "Not authenticated" };
      }

      if (role !== "SEEKER" && role !== "RECRUITER") {
        return { success: false, error: "Invalid role" };
      }

      await prisma.user.update({
        where: { id: session.user.id },
        data: { role: role as Role },
      });

      // Trigger session refresh so JWT picks up the new role
      // (Auth.js v5: use update() from useSession on client, or let middleware handle it)

      const redirectTo = role === "SEEKER" ? "/seeker/onboarding" : "/recruiter/onboarding";
      return { success: true, redirectTo };
    }
    ```

    **Part B: Create page src/app/auth/select-role/page.tsx**

    IMPORTANT: All UI is pre-built. However, /auth/select-role is a NEW page with no pre-built UI. Create a minimal, functional page using existing UI primitives (Button from @/components/ui/button). Do NOT build elaborate UI — this is a simple two-button role selection.

    ```typescript
    "use client";

    import { useState } from "react";
    import { useRouter } from "next/navigation";
    import { Button } from "@/components/ui/button";
    import { setUserRole } from "@/app/actions/auth/set-role";

    export default function SelectRolePage() {
      const router = useRouter();
      const [loading, setLoading] = useState<"SEEKER" | "RECRUITER" | null>(null);
      const [error, setError] = useState<string | null>(null);

      const handleSelect = async (role: "SEEKER" | "RECRUITER") => {
        setLoading(role);
        setError(null);
        try {
          const result = await setUserRole(role);
          if (!result.success) {
            setError(result.error);
            return;
          }
          router.push(result.redirectTo);
          router.refresh();
        } catch {
          setError("Something went wrong. Please try again.");
        } finally {
          setLoading(null);
        }
      };

      return (
        <div className="min-h-screen flex items-center justify-center bg-background">
          <div className="max-w-md w-full mx-auto p-8 space-y-8">
            <div className="text-center space-y-2">
              <h1 className="text-3xl font-bold text-foreground">Welcome to Hiretivo</h1>
              <p className="text-muted-foreground">Are you looking for work, or looking to hire?</p>
            </div>

            {error && (
              <p className="text-sm text-destructive text-center">{error}</p>
            )}

            <div className="grid grid-cols-2 gap-4">
              <Button
                onClick={() => handleSelect("SEEKER")}
                disabled={loading !== null}
                variant="outline"
                size="lg"
                className="h-24 flex-col gap-2 text-base"
              >
                {loading === "SEEKER" ? "Setting up..." : "I'm looking for work"}
              </Button>

              <Button
                onClick={() => handleSelect("RECRUITER")}
                disabled={loading !== null}
                size="lg"
                className="h-24 flex-col gap-2 text-base"
              >
                {loading === "RECRUITER" ? "Setting up..." : "I'm hiring"}
              </Button>
            </div>
          </div>
        </div>
      );
    }
    ```

    The page is minimal by design — it will only be seen by Google OAuth new users for a few seconds before they're redirected to onboarding.
