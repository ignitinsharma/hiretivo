# Phase 5 — Apply Wizard + Assisted Submit Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task. Steps use checkbox (`- [ ]`) syntax.
> Written by the main planning session against the canonical spec + DATA-MODEL (2026-07-02). Authoritative over any agent-reconstructed duplicates.

**Goal:** The core product loop — a stepper wizard that tailors a resume + cover letter to a JD, renders the ATS-safe PDF, assists the user through submitting on the source ATS, and persists the full application record.

**Architecture:** Prisma migration extends `Application` (per DATA-MODEL Phase 5, verbatim). New module `src/modules/seeker/apply/` hosts the wizard UI; route `/dashboard/applications/[id]`. Wizard consumes Phase-4 AI routes (optimize-resume, cover-letter), Phase-3b `renderResumePdf`, and `ApplicationDefaults` (3a). Submit step is ASSISTED: PDF → R2, open `externalApplyUrl` in new tab, copy-paste cheatsheet from ApplicationDefaults+profile, per-field `submittedFormData` stored (extension-ready for Phase 8.5). Credit consumed only on success (Phase-4 metering).

**Tech Stack:** Next.js App Router, Prisma, TanStack Query, RHF+Zod, R2, existing AI routes.

- Branch: `staging` pull → `feature/pivot-p5-wizard` → PR into `staging`.
