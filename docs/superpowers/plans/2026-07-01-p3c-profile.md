> **⚠️ RECONCILE BEFORE EXECUTION:** This plan was written while the canonical DATA-MODEL spec was missing (docs/ wipe, 2026-07-01) — enum/model definitions in here were reconstructed and DRIFT from canon. `docs/superpowers/specs/2026-07-01-pivot-DATA-MODEL.md` (restored 2026-07-02) is AUTHORITATIVE for all models/enums/fields: use its `WorkAuthStatus` (CITIZEN/PERMANENT_RESIDENT/WORK_VISA/NEEDS_SPONSORSHIP/STUDENT/OTHER), `SelfIdGender`, `SelfIdAnswer`, `Certification`, `ApplicationDefaults` VERBATIM, replacing any differing definitions below.

> Pivot v3 "apply-faster" tool. One branch/PR into `staging`. Code-plan written just-in-time; every task ends in one commit. Progress = checkboxes + git log.

## Goal

Ship a seeker-facing **Profile** page at `/seeker/profile` (Tsenta-style: header + completeness %, Documents, Experience, Education, Skills, Certifications, Projects, and an **Application Defaults** section) plus the **settings-side edit forms** (React Hook Form + Zod) for each section. This phase is where we **collect `ApplicationDefaults`** — the ATS-form-fill payload (location, contact, GLOBAL work-authorization, work preferences, optional US-EEO self-ID) — because onboarding (Phase 1c) is progressive and defers these fields until first apply. The Honest/Aggressive resume+cover optimize toggle also lives here (settings). Resume Preview/Upload/Download reuses the Phase-3b renderer; cover-letter default sections are captured here.

Everything is **read/preview on `/seeker/profile`**, **edit on `/seeker/settings`** — matching the existing split already in the codebase (`src/app/seeker/settings/page.tsx` renders section components from `src/modules/seeker/settings/`). New profile-specific code lives in the new module `src/modules/seeker/profile/`.

## Architecture

- **Read view** — `src/app/seeker/profile/page.tsx` (client page) rendered inside the existing `src/app/seeker/layout.tsx` (AuthGuard SEEKER + `["seeker-settings"]` prefetch already wired). Reuses the warm `["seeker-settings"]` query plus a new `["seeker-application-defaults"]` query. Read-only section cards live in `src/modules/seeker/profile/components/`.
- **Edit forms** — extend the existing settings surface. Reuse the shipped sections (`PersonalInfoSection`, `SocialProfilesSection`, `SkillsSection`, `WorkExperienceSection`, `EducationSection`, `ResumeSection`). Add **new** edit sections for Certifications, Projects, Application Defaults, and the Optimize-mode toggle — all following the exact same RHF+Zod+TanStack-Query+service pattern as `PersonalInfoSection.tsx`.
- **Data layer** — new API routes under `src/app/api/seeker/` (mirrors `PATCH /api/seeker/settings`): auth → role → rate-limit → Zod `safeParse` → `prisma.$transaction` → `NextResponse.json({ data })`. Client mutates via `seekerService` (`src/services/seeker.service.ts`) with `queryClient.invalidateQueries`.
- **Schemas** — new Zod files in `src/lib/validations/` (kebab-case `*.schema.ts`), client + server. Enums come from `src/constants/enums.ts` (no string unions).
- **Resume** — Preview/Download call the Phase-3b renderer (`src/lib/resume/render.ts`, produces R2 key via `R2_KEYS.resume`); Upload reuses the shipped `ResumeSection` + `uploadService.uploadResume`.

  /*
   * getProfileCompleteness
   * Percent of profile sections a seeker has filled — drives the header ring
   * and nudges the seeker to complete Application Defaults before first apply.
   * @param input - flags for each section's presence
   * @returns integer 0-100 (weighted equally across sections)
   */
  export interface ProfileCompletenessInput {
    hasBasics: boolean;      // name + headline + location
    hasResume: boolean;      // resumeKey present
    hasExperience: boolean;
    hasEducation: boolean;
    hasSkills: boolean;
    hasApplicationDefaults: boolean; // contact + work-auth answered
  }

  export function getProfileCompleteness(input: ProfileCompletenessInput): number {
    const flags = Object.values(input);
    const done = flags.filter(Boolean).length;
    return Math.round((done / flags.length) * 100);
  }
