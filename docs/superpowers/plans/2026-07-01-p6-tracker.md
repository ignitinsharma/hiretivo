# Phase 6 — Application Tracker (Kanban + Interview-Rate Analytics)

> **Pivot v3 · Phase 6 of 13.** Seeker-only "apply faster" tool. This phase gives the seeker a
> place to *manage* everything they applied to: a drag-and-drop kanban board, per-card notes,
> a status-change audit trail, CSV import/export, quick actions to the artifacts stored at apply
> time, and the **differentiator** — an interview-rate analytics panel (funnel + callback rate by
> match-band). Spine position: `… → 5 → (6 ∥ 7) → 8`. Depends on Phase 5 (apply wizard) having
> stored per-application artifacts; falls back gracefully when artifacts are absent.

---

## Goal

Ship `src/modules/seeker/tracker/` + a kanban board (`Applied / Ghosted / Interviewing / Rejected / Offer`)
backed by `GET/POST /api/seeker/tracker`, drag-to-change-status that persists `Application.status`
**and** appends to `Application.statusLog`, per-card free-text notes (`Application.notes`),
CSV import/export, card quick actions to stored artifacts, and an interview-rate analytics panel
computing the applied → response/interview → offer funnel plus callback rate by match-band.

## Architecture

```
prisma/schema.prisma
  Application  + notes String? @db.Text
               + statusLog Json?      // [{ status: AppStatus, at: ISOString }]
  enum AppStatus + GHOSTED            // new terminal-ish column between APPLIED and INTERVIEW

src/constants/enums.ts
  ApplicationStatus.GHOSTED              // mirror Prisma
  APPLICATION_STATUS_VALUES += GHOSTED
  enum TrackerColumn { APPLIED GHOSTED INTERVIEWING REJECTED OFFER }   // board columns (5)
  COLUMN_STATUS_MAP: TrackerColumn -> AppStatus[]   // grouping (INTERVIEWING=[INTERVIEW,REVIEWING], OFFER=[OFFER,HIRED])

src/lib/tracker/
  status-log.ts       appendStatusLog(), parseStatusLog()  — Json <-> typed audit array
  column-map.ts        statusToColumn(), columnToStatus()  — AppStatus <-> TrackerColumn
  analytics.ts         computeFunnel(), computeCallbackByBand()  — pure, testable
  csv.ts               toTrackerCsv(), parseTrackerCsv()  — no dep; RFC-4180-lite

src/lib/validations/tracker.ts
  trackerStatusUpdateSchema, trackerNoteSchema, trackerImportSchema  (Zod, shared client+server)

src/app/api/seeker/tracker/
  route.ts             GET (list, grouped)  ·  POST (status update + note; append statusLog)
  import/route.ts      POST (CSV upload → bulk upsert manual rows)
  export/route.ts      GET (stream text/csv of the seeker's tracker)

src/modules/seeker/tracker/
  types/tracker.types.ts
  queries/use-tracker.ts            useTracker(), useUpdateTrackerStatus(), useUpdateTrackerNote()
  queries/use-tracker-io.ts         useImportTracker(), export via window navigation
  utils/analytics.ts                re-export of lib/tracker/analytics for client charts (pure)
  components/TrackerBoard.tsx       DndContext + 5 columns  (client)
  components/TrackerColumn.tsx      droppable column + count
  components/TrackerCard.tsx        draggable card + quick actions + notes trigger
  components/TrackerCardNotes.tsx   inline free-text notes editor
  components/TrackerStatusLog.tsx   "shortlisted · 12 Jul" audit list
  components/TrackerAnalyticsPanel.tsx  funnel + callback-by-band (differentiator)
  components/TrackerImportExportBar.tsx CSV import (file input) + export (link)
  components/TrackerBoardSkeleton.tsx / TrackerEmptyState.tsx / TrackerErrorState.tsx

src/app/seeker/tracker/page.tsx    Server Component shell → renders <TrackerBoard />
```

Board is grouped server-side into the 5 `TrackerColumn`s. Drag emits a `POST /api/seeker/tracker`
with `{ applicationId, column }`; the server maps the column to its canonical `AppStatus`
(the first status in `COLUMN_STATUS_MAP[column]`), writes `status`, and appends
`{ status, at }` to `statusLog`. Notes are a separate optimistic mutation. Analytics are computed
**client-side** from the already-fetched list (pure functions in `lib/tracker/analytics.ts`) so no
extra round-trip; the same functions are unit-testable.

## Tech Stack

- **Drag-and-drop:** `@dnd-kit/core` + `@dnd-kit/sortable` (no dep present today — Task 0 adds them).
  Chosen over `react-beautiful-dnd` (unmaintained, React-18/Strict-Mode issues) and native HTML5 DnD
  (poor touch/mobile support). dnd-kit is accessible (keyboard + pointer) and touch-friendly.
- **CSV:** hand-rolled RFC-4180-lite in `lib/tracker/csv.ts` (fixed known columns, quote-escaping).
  No `papaparse` — our schema is fixed and small; avoids a dep + bundle weight.
- Existing stack: Next.js 14 App Router, Prisma 7, TanStack Query v5 (`apiClient` axios),
  Zod v4, Upstash `Ratelimit` via `createRateLimiter`, date-fns for `format`.
