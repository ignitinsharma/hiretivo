# Hiretivo — Development Rules for Codex

These rules apply to all development tasks in this project.

---

## Project Identity

- **Project:** Hiretivo — skills-based remote job portal (like Instahyre)
- **Core mechanic:** Match score = (seeker skills ∩ job required skills) / job required skills × 100
- **User types:** Job Seeker (SEEKER) and Recruiter (RECRUITER)
- **Auth:** Browse/search public. Apply requires login — show LoginModal, not redirect.

---

## Stack (DO NOT DEVIATE)

Next.js 14+, TypeScript (strict), pnpm, shadcn/ui, Tailwind, Lucide, Zustand, TanStack Query, React Hook Form, Zod, Prisma, Neon, Auth.js v5, Cloudflare R2, Upstash Redis, Resend, Vercel

---

## Import Rules

- **No barrel imports** — `import { JobCard } from "@/components/shared"` is WRONG
- **Use path aliases** — NEVER relative paths like `../../../components/ui/button`
- **Enums from single source** — import from `@/constants/enums`, NEVER from `@prisma/client`
- **Zod schemas in** `src/lib/validations/`

---

## TypeScript Rules

- NO `any` — use `unknown` and narrow it
- NO type assertions (`as SomeType`) unless documented
- All function params and returns must be typed
- NO `@ts-ignore` — fix the actual error

---

## Component Rules

- **Server Components by default** — add `'use client'` ONLY when needed (useState, useEffect, TanStack Query, Zustand, browser APIs)
- **Props always typed** — no loose `any` props
- **2+ rule** — if used in 2+ modules, put in `src/components/shared/`
- **Component order:** imports → types → component

---

## Form Rules

- Always use React Hook Form + Zod
- Zod schemas in `src/lib/validations/`, not component files
- Server actions MUST validate with Zod independently — never trust client data

---

## State Management

| State type | Tool |
|-----------|------|
| Server data | TanStack Query |
| Global UI | Zustand |
| Form state | React Hook Form |
| URL filters | useSearchParams |

---

## API Routes

- Always validate auth + role in protected routes
- Always validate request body with Zod
- Consistent response shape: `{ data?: T }` or `{ error?: string }`

---

## File Naming

- Components: PascalCase (JobCard.tsx)
- Hooks: use-kebab-case.ts
- Utils: kebab-case.ts
- Types: *.types.ts
- Zod schemas: *.schema.ts

---

## UI Code Quality

1. **Never repeat JSX** — use `.map()` with typed data arrays
2. **Extract repeated className** — use `cn()` or constants
3. **No hardcoded copy** — put in constants
4. **Handle all states** — isLoading, isError, empty
5. **Mobile-first** — `w-full md:w-1/2 lg:w-1/3`

---

## Matching Engine

- Score lives ONLY in `src/modules/matching/utils/calculate-match.ts`
- Score is integer 0-100, case-insensitive + trimmed
- Use `MatchThreshold.STRONG`, `.GOOD`, `.PARTIAL` — never hardcode 80, 60, 40

---

## Git

- Commit format: `type(scope): description`
- Branch: `feature/phase-X-description`, `fix/description`
- NEVER commit: .env*, node_modules/, .next/, secrets
